**Focus:** FreezeVLA targets a previously uncharacterised failure mode: action-freezing, where an adversarial visual perturbation causes the VLA model to enter an infinite loop of predicting the same null/hold action. Unlike attacks that cause dangerous movement, freezing attacks cause dangerous *inaction* — a robot that freezes mid-task in a safety-critical scenario (e.g., during surgery or on a factory floor) causes harm through omission.

## Key Insights

- **Inaction as a safety failure**: Safety research has focused heavily on preventing unsafe actions; FreezeVLA highlights that preventing unsafe *inaction* requires separate defences. A robot frozen in a hazardous posture or blocking an emergency path causes harm without executing a single unsafe action token.
- **Min-max bi-level optimisation**: The attack uses a bi-level objective — minimising the diversity of predicted actions while maximising the adversarial perturbation's stealthiness. This produces visually inconspicuous perturbations that reliably induce freezing.
- **Cross-prompt transferability**: Patches optimised against one instruction prompt transfer to other instructions, meaning a single adversarial object in the environment can freeze the robot across diverse task contexts — a significant real-world threat multiplier.

## Failure-First Relevance

FreezeVLA directly extends the Failure-First unsafe_action_elicitation taxonomy: action-freezing is a distinct outcome category (U6: unsafe_inaction) that requires a `safe_plan` control baseline showing the model normally completes the task. The cross-prompt transferability finding is particularly relevant to the PiCar-X platform — a single adversarial sticker placed in the operating environment could freeze the robot regardless of which task instruction is given.
